# 🔍 파일 무결성 검사기 (File Integrity Checker)

[![CI](https://github.com/yoopeace/file-integrity-checker/actions/workflows/ci.yml/badge.svg)](https://github.com/yoopeace/file-integrity-checker/actions/workflows/ci.yml)

SHA-256 해시를 이용해 파일의 변조, 삭제, 추가 여부를 탐지하는 도구.

---

## 개요

사전에 신뢰할 수 있는 환경에서 만든 기준선과 현재 파일 내용을 비교해,
파일이 몰래 수정·삭제·추가되었는지 탐지하는 학습용 무결성 검사 도구임.
디지털 포렌식에서 해시로 무결성을 검증하는 원리를 Python으로 구현함.

전문 포렌식 절차나 증거물 보관 연속성(chain of custody)을 대체하지 않음.

---

## 주요 기능

- SHA-256 해시 기반 파일 지문 생성
- 스냅샷(기준선) 저장 → `snapshot.json`
- 변조·삭제·추가된 파일 자동 탐지
- HMAC-SHA256 서명으로 스냅샷 자체의 위변조 탐지 (비밀키: 기본 `.integrity_key`, 권한 600)
- `--key-file`로 비밀키를 USB 등 검사 대상과 다른 곳에 보관 가능
- 읽지 못한 파일을 '삭제'와 구분해 '검사 실패'로 별도 보고
- 서명이나 비밀키가 없으면 검증을 중단 (fail-closed)
- 숨김 폴더도 기본 검사, 제외는 `--exclude`로 명시
- 검사 이력 로그 자동 기록 → `integrity_log.txt`
- 결과를 종료 코드로 구분해 자동화 도구와 연동 가능

## 사용 방법

### 1. 스냅샷 생성 (기준선 설정)
```bash
python3 checker.py --snapshot ./검사할폴더
```

### 2. 무결성 검증 (변조 탐지)
```bash
python3 checker.py --verify ./검사할폴더
```

### 3. 특정 폴더 제외
```bash
python3 checker.py --snapshot ./검사할폴더 --exclude .git --exclude node_modules
```

### 4. 비밀키를 다른 곳에 보관 (권장)
```bash
python3 checker.py --snapshot ./검사할폴더 --key-file /Volumes/USB/integrity.key
python3 checker.py --verify   ./검사할폴더 --key-file /Volumes/USB/integrity.key
```

기본 설정에서는 비밀키가 스냅샷과 같은 폴더에 생성됨. 그러면 스냅샷을 조작할 수 있는 사람이 키도 읽어
서명을 다시 만들 수 있으므로, 키는 검사 대상과 다른 곳(USB, 다른 서버 등)에 두고 검증할 때만 연결하는 것이 안전함.
지정한 경로에 키가 없으면 스냅샷을 만들 때 새로 만들고 그 위치를 화면에 알려줌.

`--snapshot`과 `--verify`는 동시에 지정할 수 없음.

서명을 확인할 수 없는 스냅샷을 굳이 검증해야 한다면 `--allow-unsigned`를 명시해야 함.

## 종료 코드

| 코드 | 의미 |
|------|------|
| 0 | 변경 없음 |
| 1 | 변조·삭제·추가 감지 |
| 2 | 사용법 또는 입력 오류 |
| 3 | 스냅샷·키 검증 실패 |
| 4 | 일부 파일을 검사하지 못함 |

## 실행 결과 예시

```
==================================================
    📋 무결성 검사 결과 보고서
==================================================
  스냅샷 기준 시각: 2025-01-01T10:00:00
  검사 완료 시각:   2025-01-01T10:05:00
  검사 파일 수:     2개
--------------------------------------------------

⚠️  변조된 파일 (1개):
   • doc1.txt

✅ 삭제된 파일: 없음
✅ 새로 추가된 파일: 없음
==================================================
🚨 총 1건의 변경이 감지되었습니다.
```

읽지 못한 파일이 있으면 '삭제'로 오판하지 않고 별도로 보고함.

```
✅ 삭제된 파일: 없음

❓ 검사하지 못한 파일·폴더 (1개):
   • blocked.txt → [Errno 13] Permission denied: 'blocked.txt'
==================================================

⚠️  검사하지 못한 파일·폴더가 1개 있어 결과를 확정할 수 없습니다.
```

## 유의사항

- 스냅샷 파일이 없는 상태에서 `--verify`를 실행하면 안내 메시지 출력 후 종료함
- 존재하지 않는 폴더 경로를 입력하면 오류를 안내함
- `snapshot.json`이 손상되었거나 형식이 올바르지 않은 경우 재생성을 안내함
- 스냅샷 서명이 일치하지 않으면(위변조 의심) 검증을 중단함
- 파일이나 하위 폴더를 하나라도 읽지 못하면 스냅샷을 만들지 않음 (불완전한 기준선 방지)
- 검증 중 읽지 못한 파일·폴더가 있으면 '삭제'로 판정하지 않고, 결과를 확정할 수 없다고 보고함
- 도구가 만든 파일은 이름이 아니라 실제 경로로 판단해 제외함 (사용자의 `backup/snapshot.json`은 정상 검사됨)
- `--exclude` 설정은 서명된 스냅샷에 기록됨. 검증 때 생략하면 같은 설정이 적용되고, 다른 설정을 주면 거부함 (검증 때만 폴더를 빼서 변조를 숨기는 것 방지)
- 심볼릭 링크는 따라가지 않고 '가리키는 경로'를 기록함. 링크 대상이 바뀌거나 폴더가 링크로 바꿔치기되면 탐지함
- FIFO·장치 파일 등 특수 파일은 내용을 읽지 않고 종류만 기록함 (열면 멈출 수 있어서)
- 비밀키 파일은 처음부터 소유자 전용 권한(600)으로 만들고, 빈 키 파일은 사용하지 않음
- 스냅샷은 임시 파일에 다 쓴 뒤 한 번에 교체함. 저장 중 실패해도 이전 스냅샷은 그대로 남음
- 터미널에는 결과 보고서만 표시하고, 파일별 처리 기록은 `integrity_log.txt`에만 남김

## 알려진 한계

- `--key-file`을 쓰지 않으면 비밀키가 스냅샷과 같은 폴더, 같은 소유자로 저장됨. 이 경우 스냅샷을 수정할 수 있는 계정은 대개 키도 읽을 수 있어 서명 보호가 약해짐
- `--key-file`로 키를 분리해도, 키를 보관한 매체까지 접근할 수 있는 공격자는 막지 못함
- 심볼릭 링크가 검사 폴더 밖을 가리키면, 그 대상 파일의 내용 변경은 탐지하지 않음
- 이전 버전으로 만든 스냅샷에 심볼릭 링크가 있으면, 링크 기록 방식이 달라져 첫 검증 때 변조로 표시될 수 있음. 스냅샷을 새로 만들 것을 권장함
- 파일 내용만 비교하며, 소유자·권한·수정 시각 변경은 탐지하지 않음

## 테스트

전체 테스트(71건) 실행:

```bash
python3 -m venv .venv
.venv/bin/pip install pytest
.venv/bin/pytest
```

| 파일 | 대상 |
|------|------|
| `test_checker.py` | `checker.py`의 함수들 (정제·해시·폴더 훑기·서명·스냅샷·비교·검증) |
| `test_cli.py` | 프로그램 실행 동작 (종료 코드, 망가진 스냅샷·키, 특수 파일·링크, 제외 설정) |

`main` 브랜치에 push하거나 PR을 올리면 GitHub Actions에서 테스트가 자동 실행됨.
