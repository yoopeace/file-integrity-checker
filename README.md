# 🔍 파일 무결성 검사기 (File Integrity Checker)

[![CI](https://github.com/yoopeace/file-integrity-checker/actions/workflows/ci.yml/badge.svg)](https://github.com/yoopeace/file-integrity-checker/actions/workflows/ci.yml)

SHA-256 해시를 이용해 파일의 변조, 삭제, 추가 여부를 탐지하는 도구.

---

## 개요

사전에 신뢰할 수 있는 환경에서 만든 기준선과 현재 파일 내용을 비교해,
파일이 몰래 수정·삭제·추가되었는지 탐지하는 학습용 무결성 검사 도구임.
디지털 포렌식에서 해시로 무결성을 검증하는 원리를 Python으로 구현함.

전문 포렌식 절차나 증거물 보관 연속성(chain of custody)을 대체하지 않음.

---

## 주요 기능

- SHA-256 해시 기반 파일 지문 생성
- 스냅샷(기준선) 저장 → `snapshot.json`
- 변조·삭제·추가된 파일 자동 탐지
- HMAC-SHA256 서명으로 스냅샷 자체의 위변조 탐지 (비밀키: `.integrity_key`, 권한 600)
- 읽지 못한 파일을 '삭제'와 구분해 '검사 실패'로 별도 보고
- 서명이나 비밀키가 없으면 검증을 중단 (fail-closed)
- 숨김 폴더도 기본 검사, 제외는 `--exclude`로 명시
- 검사 이력 로그 자동 기록 → `integrity_log.txt`
- 결과를 종료 코드로 구분해 자동화 도구와 연동 가능

---

## 사용 방법

### 1. 스냅샷 생성 (기준선 설정)
```bash
python3 checker.py --snapshot ./검사할폴더
```

### 2. 무결성 검증 (변조 탐지)
```bash
python3 checker.py --verify ./검사할폴더
```

### 3. 특정 폴더 제외
```bash
python3 checker.py --snapshot ./검사할폴더 --exclude .git --exclude node_modules
```

`--snapshot`과 `--verify`는 동시에 지정할 수 없음.

서명을 확인할 수 없는 스냅샷을 굳이 검증해야 한다면 `--allow-unsigned`를 명시해야 함.

## 종료 코드

| 코드 | 의미 |
|------|------|
| 0 | 변경 없음 |
| 1 | 변조·삭제·추가 감지 |
| 2 | 사용법 또는 입력 오류 |
| 3 | 스냅샷·키 검증 실패 |
| 4 | 일부 파일을 검사하지 못함 |

## 실행 결과 예시

```
==================================================
    📋 무결성 검사 결과 보고서
==================================================
  스냅샷 기준 시각: 2025-01-01T10:00:00
  검사 완료 시각:   2025-01-01T10:05:00
  검사 파일 수:     2개
--------------------------------------------------

⚠️  변조된 파일 (1개):
   • doc1.txt

✅ 삭제된 파일: 없음
✅ 새로 추가된 파일: 없음
==================================================
🚨 총 1건의 변경이 감지되었습니다.
```

읽지 못한 파일이 있으면 '삭제'로 오판하지 않고 별도로 보고함.

```
✅ 삭제된 파일: 없음

❓ 검사하지 못한 파일 (1개):
   • blocked.txt → [Errno 13] Permission denied: 'blocked.txt'
==================================================

⚠️  검사하지 못한 파일이 1개 있어 결과를 확정할 수 없습니다.
```

## 유의사항

- 스냅샷 파일이 없는 상태에서 `--verify`를 실행하면 안내 메시지 출력 후 종료함
- 존재하지 않는 폴더 경로를 입력하면 오류를 안내함
- `snapshot.json`이 손상되었거나 형식이 올바르지 않은 경우 재생성을 안내함
- 스냅샷 서명이 일치하지 않으면(위변조 의심) 검증을 중단함
- 파일을 하나라도 읽지 못하면 스냅샷을 만들지 않음 (불완전한 기준선 방지)
- 검증 중 읽지 못한 파일이 있으면 '이상 없음'이라고 단언하지 않고 결과를 확정할 수 없다고 보고함
- 도구가 만든 파일은 이름이 아니라 실제 경로로 판단해 제외함 (사용자의 `backup/snapshot.json`은 정상 검사됨)

## 알려진 한계

- 비밀키(`.integrity_key`)가 검사 대상과 같은 컴퓨터에 저장됨. 관리자 권한을 가진 공격자는 키를 읽어 서명을 위조할 수 있으므로, 키를 별도 매체에 보관하는 것이 안전함
- 심볼릭 링크는 링크가 가리키는 파일 내용을 기준으로 해시를 계산함
- 파일 내용만 비교하며, 소유자·권한·수정 시각 변경은 탐지하지 않음

## 테스트

전체 테스트(37건 = pytest 28건 + unittest 9건) 실행:

```bash
python3 -m venv .venv
.venv/bin/pip install pytest
.venv/bin/pytest
```

pytest 없이 실행 (서명 관련 9건만 해당):

```bash
python3 -m unittest test_checker
```

`test_hashing.py`, `test_robustness.py`는 pytest 기능을 사용하므로 pytest로만 실행됨.

`main` 브랜치에 push하거나 PR을 올리면 GitHub Actions에서 테스트가 자동 실행됨.
